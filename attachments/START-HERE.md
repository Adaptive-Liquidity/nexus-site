# Start Here - Nexus-IQ Cinematic Grok Handoff

This is the operator entrypoint for the complete Nexus-IQ cinematic website package.

## What this package does

It gives Grok:

- a source-faithful extraction of the supplied cinematic website tutorial;
- Nexus-IQ product, claims, design-system, and repository constraints;
- a current production-extension stack with clear adoption gates;
- an evidence-led marketing, research, proof, curiosity, and ethical-demand system;
- an autonomous phase plan with recovery rules and verification evidence;
- a compact checklist and reusable prompt library.

It does **not** authorize deployment, publishing, pushing, merging, paid API usage, external uploads, account changes, credentials, or desktop automation.

1. Open the Grok Build workspace for [Adaptive-Liquidity/nexus-site](https://github.com/Adaptive-Liquidity/nexus-site).
2. Confirm the workspace contains the existing Nexus-IQ application rather than a blank scaffold.
3. Attach all eight files above.

5. If you want Grok to use a supplied image, video, GLB, font, or other asset, attach it and include its source/license status.

Do not deploy, publish, push, merge, open a pull request, upload to external services, spend credits, run external migrations, or change credentials without my separate authorization.

## What should happen first

Grok should:

1. read the repository instructions and all attached files;
2. inspect the current branch, files, dependencies, existing changes, tokens, copy, claims, evidence, research surfaces, routes, assets, and every build/migration script;
3. start or recover the existing live preview;
4. capture and visually inspect baseline desktop, tablet, and mobile screenshots;
5. exercise navigation and the DemoPlayer;
6. create `docs/build/CINEMATIC_INTEGRATION_PLAN.md`;
7. choose one implementation direction and record why simpler alternatives were accepted or rejected;
8. implement, inspect, correct, and verify phase by phase.

If Grok starts installing packages or generating media before auditing the current site, redirect it with:

```text
Stop implementation. Return to Phase 0 and Phase 1 of the attached autonomous contract. Inspect and run the existing site, capture baseline screenshots, exercise the DemoPlayer, and record the exact integration map before changing dependencies or creating assets.
```


### Allow deployment or GitHub mutation

Do not combine this with the initial build prompt. Give a separate instruction naming the exact repository, branch, target environment, and allowed action after the local completion report passes.

## Expected completion evidence

Do not accept "done" without:

- baseline and final screenshot paths;
- exact changed files and assets;
- dependencies added or removed with reasons;
- media dimensions, formats, durations, and byte sizes;
- typecheck, lint, and safe build results, including the exact command and whether the migration step was intentionally skipped;
- browser checks at mobile, tablet, and desktop widths;
- navigation and DemoPlayer interaction results;
- reduced-motion, keyboard, focus, contrast, and media-fallback results;
- claim/maturity preservation confirmation;
- remaining limitations and deliberately deferred work;
- confirmation that the live preview remains healthy.

## If Grok reports a blocker

A valid blocker requires unavailable authority or information, such as credentials, legal approval, an external service or database change, or permission to publish. A failed dependency, poor generated asset, broken first implementation, or difficult visual bug is not by itself a blocker; Grok must use the fallback ladder in the autonomous prompt and continue.
