# Nexus-IQ Cinematic Website Build Checklist

## Usage

This checklist adapts the supplied tutorial to the existing Nexus-IQ application. It does not authorize a new scaffold, a site-wide rewrite, external services, paid APIs, desktop automation, deployment, or GitHub mutation.

## Preflight and product truth

- [ ] Read `START-HERE.md`, `README.md`, the autonomous prompt, tutorial report, production extensions, prompt pack, and this checklist.
- [ ] Read the live repository instructions, project memory, `package.json`, design tokens, locked copy, transaction beats, and claims registry.
- [ ] Confirm the existing React 19 + TanStack + Vite + Tailwind application is populated; do not follow generic blank-scaffold examples that conflict with live source.
- [ ] Record branch, baseline commit, existing changes, and exact files proposed for modification.
- [ ] Inspect every build and migration script; classify external-mutation risk without printing credential values.
- [ ] Select the safe local build path before implementation: full build only for confirmed local/non-destructive migration, otherwise compile-only Vite build.
- [ ] Preserve unrelated/user changes.
- [ ] Start or recover the existing preview through `startup.sh`.
- [ ] Capture and visually inspect baseline mobile, tablet, and desktop screenshots.
- [ ] Exercise navigation and the DemoPlayer before editing.
- [ ] Create `docs/build/CINEMATIC_INTEGRATION_PLAN.md`.

## Direction

- [ ] Define one Nexus-IQ-specific visual premise: a consequential action approaching a controlled commit boundary.
- [ ] Map Stage → Constrain → Validate → Commit/Abort → Emit onto Intent → Gap → Execute.
- [ ] Preserve the locked hero premise, transaction sequence, maturity labels, limitations, evidence links, routes, and DemoPlayer.
- [ ] Use existing semantic tokens and forensic systems modernism.
- [ ] Reject tutorial geology/planet content, `#522DFF`, Playfair styling, pricing, fictional routes, and “$50,000” claims.
- [ ] Reject generic AI brains, robots, neon circuits, crypto motifs, random particles, excessive glass, and repeated glowing cards.
- [ ] Define desktop/mobile composition, negative space, scroll range, reduced-motion behavior, and media-to-surface handoff.
- [ ] Approve one direction and remove abandoned prototypes after integration.

## Technology decision gate

- [ ] Classify the surface as one primary path: DOM/CSS, native scroll/view transition, video, shader, or interactive 3D.
- [ ] Inspect existing dependencies before adding anything.
- [ ] Prefer existing code plus CSS, WAAPI, CSS Scroll-Driven Animations, View Transitions, `IntersectionObserver`, `requestAnimationFrame`, SVG/canvas, and HTML video.
- [ ] Use GSAP + ScrollTrigger only for a complex synchronized pinned timeline that native code cannot implement cleanly.
- [ ] Use Motion only for a real React layout/state choreography requirement; do not overlap it with GSAP.
- [ ] Use native scrolling by default; Lenis requires documented need and anchor/keyboard/touch/sticky/history/reduced-motion tests.
- [ ] Use OGL for a shader-only surface before adopting a 3D scene graph.
- [ ] Use Three.js + R3F v9 only for genuine interactive 3D; import only necessary Drei helpers.
- [ ] Do not install competing stacks or “anti-slop” component galleries by default.
- [ ] Record each new dependency’s requirement, alternatives, cost, fallback, removal condition, and verification evidence.
- [ ] Run a dependency/security audit if dependencies change.

## Asset and media contract

- [ ] Create or update `docs/build/CINEMATIC_ASSET_MANIFEST.md`.
- [ ] Record origin, provenance, license, tool/model/version, prompt/settings, dimensions, duration, codec, original/final size, transformations, fallback, and crop behavior.
- [ ] Generate or select a stable focal asset with intentional negative space.
- [ ] Animate only the approved subject/state; lock camera, scale, framing, and composition unless the storyboard explicitly requires otherwise.
- [ ] Reject outputs that zoom, pan, reframe, hallucinate text/UI, imply unsupported capability, or look generic.
- [ ] Store approved assets under `public/media/cinematic/` with descriptive filenames.
- [ ] Provide a poster/still and media-error fallback.
- [ ] Keep critical product meaning in semantic code, never only in video or generated pixels.
- [ ] Use muted `playsInline` background video; loop only when seamless and useful.
- [ ] Do not autoplay a scroll-scrubbed video against `currentTime` control.
- [ ] Verify focal crop and text contrast across every frame and target viewport.
- [ ] Prefer composition, crop, text placement, and asset correction over blanket overlays; reject the placement if accessibility still fails.
- [ ] Record byte sizes and prevent unnecessary mobile/initial loading.

## Intent → Gap → Execute implementation

- [ ] Evolve the current hero or `HeroSchematic`; do not discard working product structure without evidence.
- [ ] Preserve headline, supporting copy, CTAs, maturity strip, transaction chrome, and semantic heading order.
- [ ] Carry the visual into Gap only while it clarifies the missing transaction boundary.
- [ ] Keep the transaction rail and narrative readable.
- [ ] If scroll-linked, wait for metadata, clamp progress, schedule via `requestAnimationFrame`, support reverse scroll, and clean up listeners/frames.
- [ ] Use `IntersectionObserver` for discrete reveals.
- [ ] Ensure sticky/pinned behavior releases correctly and never traps later content.
- [ ] Provide a complete static/simplified reduced-motion experience.
- [ ] Transition into existing surface tokens with no hard seam or compositing rectangle.
- [ ] Keep the DemoPlayer interactive, functional, and visually dominant as product proof.

## Conditional 3D delivery

- [ ] Do not attempt Blender installation or Blender MCP control inside Grok Build.
- [ ] Use only an explicitly authorized, trusted desktop Blender workflow.
- [ ] Validate supplied GLB/glTF assets.
- [ ] Remove unused scenes/nodes/materials/attributes/clips and resize textures.
- [ ] Evaluate KTX2/Basis and Meshopt/Draco with measured compatibility and decode cost.
- [ ] Preserve required node and animation-clip names.
- [ ] Record before/after sizes and optimization steps.
- [ ] Lazy-load the 3D surface, cap DPR, use demand rendering where possible, pause hidden/offscreen work, and dispose GPU resources.
- [ ] Test static, reduced-motion, no-WebGL, context-loss, desktop, and mobile fallbacks.

## External-service gate

- [ ] Treat FLUX, Kling, Luma, Cloudinary, and Mux as optional credentialed services.
- [ ] Without separate authorization, do not create accounts, spend credits, upload assets, configure remote MCPs, change credentials, run external database migrations, or mutate external resources.
- [ ] When authorized, stay within the named service, purpose, spend limit, data boundary, and rollback scope.
- [ ] Never send repository source, claims data, credentials, private customer data, or unrelated assets to an external service.
- [ ] Verify current official model/API/pricing/terms immediately before authorized use.
- [ ] Record external asset IDs, delivery settings, retention, and rollback/delete steps.

## Content, research, proof, and ethical demand

- [ ] Audit public copy, claims, maturity labels, evidence links, methods, authorship, review dates, and open curiosity loops before changing content.
- [ ] Preserve the Nexus-IQ message spine: category tension → consequence → mechanism → proof → maturity → evaluator action.
- [ ] Map every material claim to evidence or label it clearly as hypothesis, target, experimental, in development, or proposed.
- [ ] For numerical claims, show method, unit, denominator, comparator, conditions, uncertainty, and date.
- [ ] Distinguish what each Proof Capsule proves from what it does not prove.
- [ ] Use progressive disclosure for executive, technical, and evaluator depths without changing the underlying truth.
- [ ] Make curiosity specific and answerable; close every open loop with mechanism or evidence.
- [ ] Use only earned urgency based on real risk, change, availability, or cost of inaction.
- [ ] Reject fake countdowns, false scarcity, fabricated activity, invented testimonials/logos, buried limitations, and other dark patterns.
- [ ] Record contradictory, negative, and null evidence; do not cherry-pick only supportive sources.
- [ ] Label systematic, scoping, and narrative reviews accurately; publish search/method notes appropriate to the claimed method.
- [ ] Keep generated media atmospheric; never present it as product, benchmark, security, or research evidence.
- [ ] Do not add analytics, experiments, structured-data claims, outreach, paid promotion, or publishing without scope and authorization.
## Site-wide harmonization

- [ ] Inspect the remaining beats and routes after Intent → Gap → Execute passes.
- [ ] Harmonize spacing, density, token use, borders, and transitions only where necessary.
- [ ] Preserve the dark-runtime versus archive-evidence semantic split.
- [ ] Do not add motion to every section.
- [ ] Add at most one later cinematic bridge only when it materially improves closure and remains within budget.
- [ ] Do not duplicate the same hero treatment across routes.
- [ ] Do not change locked copy or maturity for visual convenience.

## Verification

- [ ] Test approximately 390 × 844, 768 × 1024, and 1440 × 900.
- [ ] Capture and inspect final screenshots at the same baseline states.
- [ ] Compare before/after for legibility, hierarchy, density, cropping, and generic effects.
- [ ] Test keyboard navigation, visible focus, landmarks, heading order, controls, links, and 200% zoom.
- [ ] Test `prefers-reduced-motion: reduce`; all content remains available.
- [ ] Test forward and reverse scroll behavior.
- [ ] Test media failure, poster loading, feature-detection fallbacks, and no-WebGL fallback when applicable.
- [ ] Check every public route, navigation path, and critical DemoPlayer commit/abort interaction.
- [ ] Check console errors, hydration warnings, unhandled rejections, and failed network requests.
- [ ] Confirm no maturity qualifier, limitation, evidence link, method, provenance statement, or claim-to-evidence relationship was lost.
- [ ] Confirm every added curiosity loop resolves and no fake scarcity, fabricated proof, or dark pattern was introduced.
- [ ] Run `npm run typecheck`.
- [ ] Run `npm run lint` and distinguish any pre-existing baseline.
- [ ] Inspect the build chain before execution. Run `npm run build` only when its migration is confirmed local and non-destructive; otherwise run `npm exec -- vite build`, record the migration as intentionally skipped/not authorized, and do not claim it passed.
- [ ] Re-run the exact failing check after every fix.
- [ ] Keep the live preview healthy through the established startup contract.

## Completion report

- [ ] Finish `docs/build/CINEMATIC_INTEGRATION_PLAN.md` truthfully.
- [ ] Create `docs/build/CINEMATIC_INTEGRATION_REPORT.md`.
- [ ] Report exact changed files/assets, dependencies, selected runtime path, rejected alternatives, media sizes, screenshots, browser checks, command results, claim-safety result, limitations, and deferred work.
- [ ] Update project memory only with verified facts.
- [ ] Do not claim completion from code alone.
- [ ] Do not deploy, publish, push, merge, or open a pull request without separate authorization.
